# 조각 1 테스트 (초안)

> **AI 초안이다.** 팀 결정(11/12): 테스트는 AI가 초안을 쓰고 사람이 한 줄씩 검토한다.
> 검토할 때 각 테스트의 기대값이 노션 "4. 밖에서 보이는 규칙"과 같은지 확인하고,
> 설명 못 하는 줄은 승인하지 않는다. 승인 전에는 AI가 이 파일들을 고치지 않는다.

## 구성

```
include/store.h          단위 테스트가 부르는 해시 테이블 인터페이스 (11/12 팀 확정)
tests/check.h            CHECK / RUN / FINISH 매크로 (의존성 없음)
tests/unit/test_store.c  U1~U18. store를 직접 호출, 시각은 테스트가 넘김
tests/e2e/resp_client.*  소켓으로 RESP를 주고받는 도우미 (지도만 알면 되는 코드)
tests/e2e/test_resp.c    E1~E36. 띄워 둔 서버에 붙어서 응답을 바이트 단위로 비교
tests/Makefile
```

## 실행

```sh
cd tests
make unit                         # src/store.c 구현이 있어야 링크됨 (STORE_SRC=로 위치 변경)
MINI_REDIS_PORT=6380 make e2e     # 서버를 먼저 띄워 둘 것
```

E8·E9·E10·E12·E13·E26은 실제로 1.1초씩 기다려서 전체 외부 테스트는 약 7초 걸린다.

## 지금 상태

- 단위 테스트: 구현 없이 "항상 없음"만 돌려주는 빈 store로 돌리면 16개 중 13개 실패(빨간불).
  통과하는 3개(U3, U13, U18)는 "없어야 한다"를 확인하는 테스트라 빈 구현에서도 통과하는 게 맞다.
- 외부 테스트: 컴파일 확인, 서버가 없으면 연결 실패로 종료(코드 2). 응답 읽기 도우미는 가짜 서버로 E1 한 개만 확인했다.
  **실제 서버로는 아직 한 번도 안 돌려봤다.**

## 테스트를 쓰다 생긴 결정

| 내용 | 지금 테스트의 가정 | 상태 |
| --- | --- | --- |
| 단위 테스트가 부를 함수 모양 (`include/store.h`) | 시각은 호출자가 넘김(`now_ms`), 키·값은 (포인터, 길이), 영구는 `STORE_NO_EXPIRE`(-1), 저장은 복사본 | ✅ 11/12 확정 |
| 서버 위치 | 127.0.0.1, 포트는 `MINI_REDIS_PORT`(기본 6380). 서버는 미리 띄워 둠 | 설정값 |
| `EX +1`, `EX " 1"` | 에러로 정함(11/12). 테스트에는 아직 없음 | ✅ |
| 1MB 초과 테스트는 길이 머리만 보냄 | 본문까지 보내면 서버가 안 읽고 끊을 때 에러 응답을 못 받아 테스트가 흔들림 (E16) | 설명용 |

## 조각 1에서 정하지 않고 테스트도 하지 않는 것 (써보다 필요하면 그때)

- `*`로 시작하지 않는 요청 (`GET k\r\n`, 실제 Redis의 인라인 명령)
- `*0\r\n`(빈 배열), `*-1\r\n`

## U5~U7을 하나로 합친 이유

테스트는 해시 함수가 어느 키를 어느 칸에 넣는지 모른다고 가정했다.
키 24개를 칸 8개에 넣으면 어떤 칸에는 3개 이상이 들어간다(비둘기집).
키를 하나씩 지워보는 걸 24번 반복하면 그 칸의 맨 앞·가운데·맨 끝이 한 번씩은 지워지므로,
"지운 키만 없고 나머지는 전부 있다"를 매번 확인하면 세 경우가 다 덮인다.

## 검증할 때 해볼 것 (일부러 깨뜨리기)

구현이 나온 뒤, 아래처럼 망가뜨렸을 때 테스트가 잡는지 본다.

- 만료 비교를 `>`에서 `>=`로 바꾸기 → U12가 실패해야 함
- 키 비교를 `strcmp`로 바꾸기 → U8이 실패해야 함
- 체인 삭제에서 이전 노드 연결을 빼먹기 → U5~U7이 실패해야 함
- SET 검사 전에 기존 값을 먼저 지우기 → E6·E7·E32가 실패해야 함
- 요청 조각을 모으지 않고 recv 한 번에 처리하기 → E22가 실패해야 함
